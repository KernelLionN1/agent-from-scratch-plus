## 一、先理解：为什么需要容错？

Day2 的系统在"一切正常"时跑得很漂亮。但真实世界不是这样的：

```
正常情况：Planner → Coder1 → Coder2 → Reviewer  ✅

真实世界：
  ├── DeepSeek API 返回 429（限流） → 整个流程中断
  ├── 网络超时 30s → 请求挂起
  ├── Coder1 失败 → gather 抛异常，Coder2 的结果也丢了
  ├── 整体超时 → 所有已完成结果被丢弃
  └── 两个 Agent 同时改 SharedState → 版本冲突，直接放弃
```

## 二、四个修复

### 修复 #10：LLM 指数退避重试 — `llm_client.py`

```
修复前：裸调 API，一次失败 = 整体崩溃
修复后：3 次重试，间隔 1s → 2s → 4s

异常分类：
  可重试：APITimeoutError / RateLimitError / APIConnectionError / InternalServerError
  不可重试：AuthenticationError / BadRequestError（重试没用，直接抛）

Java 类比：@Retryable(maxAttempts=3, backoff=@Backoff(delay=1000, multiplier=2))
```

### 修复 #11：并行任务容错 — `orchestrator.py`

```
修复前：asyncio.gather(*tasks)  ← 一个失败全部抛异常
修复后：asyncio.gather(*tasks, return_exceptions=True)  ← 异常作为返回值

结果处理：isinstance(r, Exception) → 转为 {"error": str(r)} 的 dict
效果：Coder1 挂了不影响 Coder2，Reviewer 仍能审核成功部分
```

### 修复 #12：超时 + 部分结果收集 — `orchestrator.py`

```
修复前：asyncio.wait_for → 超时抛 TimeoutError → 结果全丢
修复后：asyncio.wait + ensure_future → 返回 (done, pending)

done   → 已完成任务的结果（保留！）
pending → 未完成的任务 .cancel() → 标记 "timeout"

asyncio.wait vs wait_for：
  wait_for: 超时=抛异常=全丢
  wait:     超时=返回两个集合=已完成的不丢
```

### 修复 #13：乐观锁自动重试 — `shared_state.py`

```
新增方法：update_with_retry(key, compute_new_value, max_retries=3)

三步循环（Read → Compute → Write）：
  ① 读最新值 + 当前版本号（加锁）
  ② 计算新值（无锁，不阻塞读）
  ③ 加锁检查版本号 → 匹配则写入 / 不匹配回到①

使用：state.update_with_retry("counter", lambda v: (v or 0) + 1)

Java 类比：@Version + @Retryable(maxAttempts=3)
```

## 三、Java 对照表

| Python | Java |
|--------|------|
| `for attempt in range(1, max+1)` + `time.sleep(2**n)` | `@Retryable(backoff=@Backoff(multiplier=2))` |
| `return_exceptions=True` | `CompletableFuture.allOf()` 默认不抛 |
| `asyncio.wait(tasks, timeout)` | `executor.invokeAll(tasks, timeout, unit)` |
| `asyncio.ensure_future(coro)` | `CompletableFuture.supplyAsync(() -> ...)` |
| `update_with_retry(key, fn)` | `@Version` + `@Retryable` |

## 四、动手实验

### 实验：验证乐观锁三步循环

```python
from src.shared_state import SharedState

state = SharedState()
state.set("count", 0)

# 连续累加 5 次
for _ in range(5):
    ok = state.update_with_retry("count", lambda v: (v or 0) + 1)
    assert ok

print(f"count = {state.get('count')}")  # 预期: 5
```
