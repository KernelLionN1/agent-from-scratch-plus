## 七、通用类：LLM 返回格式异常（3 坑）

这是跨天都存在的问题，独立成章。

| # | 踩坑 | 现象 | 解决方案 |
|---|------|------|---------|
| 32 | LLM 返回缺失字段 | `response["content"]` KeyError | `response.get("content", "")` 安全取值 |
| 33 | tool_calls 的 arguments 不是合法 JSON | `json.loads("1+2")` → 报错 | try/except + 降级为 `{}` |
| 34 | LLM 说了话但没调工具 | "好的我来算" → 没有 tool_calls | 先检查 `tool_calls`，再取 `content`；system prompt 写死"必须调工具" |

### 兜底策略（通用模板）

```python
def safe_parse_llm_response(response: dict) -> dict:
    """防御式解析 LLM 响应，多层兜底"""
    
    # 1. 字段安全取值
    content = response.get("content") or ""
    tool_calls = response.get("tool_calls") or []
    
    # 2. 清洗 tool_calls
    clean_calls = []
    for tc in tool_calls:
        name = tc.get("name") or tc.get("function", {}).get("name", "")
        if not name:
            continue  # 没名字的跳过
        
        # 3. 安全解析 arguments
        args_raw = tc.get("arguments", "{}")
        if isinstance(args_raw, str):
            try:
                args = json.loads(args_raw)
            except json.JSONDecodeError:
                args = {}  # 解析失败 → 空 dict
        else:
            args = args_raw
        
        # 4. 解包可能的嵌套
        if isinstance(args, dict) and len(args) == 1:
            key = list(args.keys())[0]
            if isinstance(args[key], dict) and key not in ("expression", "query", "input"):
                args = args[key]  # 解包嵌套 ({kwargs: {...}} → {...})
        
        clean_calls.append({"name": name, "arguments": json.dumps(args)})
    
    return {
        "content": content,
        "tool_calls": clean_calls if clean_calls else None,
    }
```

### 核心原则

1. **永远用 `.get()` 不用 `[]`** — LLM 的输出不可信
2. **JSON 解析必须 try/except** — arguments 可能是 `"1+2"` 这种非 JSON
3. **先检查 tool_calls 再取 content** — 顺序反了会导致"说话但不干活"
4. **嵌套解包** — 不同 LLM 厂商的 args 格式不同（OpenAI 平铺，DeepSeek 嵌套）
5. **兜底空值不抛异常** — 宁可返回空也不要 crash 整个流程（Day6 修复） |
