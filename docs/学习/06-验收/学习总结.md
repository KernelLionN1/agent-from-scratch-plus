### 6.2 消息队列 — Kafka 统一方案

```python
# 用 Kafka 替代 MQ + 流数据（一套中间件）
from kafka import KafkaProducer, KafkaConsumer

# ── 发送任务（替代 RabbitMQ）──
producer = KafkaProducer(bootstrap_servers="kafka:9092")
producer.send("agent.tasks", json.dumps({
    "task_id": "abc", "user_id": "u1", "question": "本月销售额"
}).encode())

# ── Worker 消费 ──
consumer = KafkaConsumer("agent.tasks", group_id="ai-workers")
for msg in consumer:
    task = json.loads(msg.value)
    answer = agent.run(task["question"])
    producer.send("agent.results", json.dumps({"task_id": task["task_id"], "answer": answer}).encode())
```

**Kafka 一个集群管两类数据：**
```
agent.tasks        ← Java→Python 任务（低吞吐，秒级，MQ 职责）
sensor.readings    ← 园区传感器（高吞吐，毫秒级，Flink 消费）
agent.results      ← Python→Java 回传
dead.letter        ← 失败重试 3 次后人工处理
```

### 6.3 缓存 — Redis（Python + Java 双端）

```python
# ── Python AI 中台：缓存 LLM 结果 + Session ──
import redis, hashlib, json

r = redis.Redis(host="localhost", port=6379, decode_responses=True)

def cached_agent_run(question: str, ttl: int = 300) -> str:
    """相同问题 5 分钟内走缓存，不调 LLM"""
    key = f"llm:{hashlib.md5(question.encode()).hexdigest()}"
    cached = r.get(key)
    if cached:
        return json.loads(cached)  # 命中 → 零延迟
    result = agent.run(question)
    r.setex(key, ttl, json.dumps(result))  # TTL 5 分钟
    return result

# ── Session 存储（替代内存 dict）──
def save_session(session_id: str, data: dict, ttl: int = 3600):
    r.setex(f"session:{session_id}", ttl, json.dumps(data))

def load_session(session_id: str) -> dict | None:
    raw = r.get(f"session:{session_id}")
    return json.loads(raw) if raw else None
```

```java
// ── Java 业务中台：缓存接口结果（Spring Cache）──
@Service
public class AiPlatformClient {
    @Cacheable(value = "ai-responses", key = "#question.hashCode()")
    public String askAgent(String question) {
        return restTemplate.postForObject("http://ai-backend/api/chat", question, String.class);
    }
    // @Cacheable 自动：查 Redis → 命中返回 → 未命中调接口 → 存 Redis
}

// application.yml
// spring.cache.type=redis
// spring.cache.redis.time-to-live=300000  # 5分钟 TTL
```

**TTL 策略：**

| 数据类型 | TTL | 原因 |
|---------|:--:|------|
| LLM 结果缓存 | 5 min | 相同问题短期内不重复调 |
| Session | 1 hour | 会话超时自动清理 |
| 限流计数器 | 1 min | slowapi 令牌桶 |
| text2sql 结果 | 10 min | 数据库变化慢，可缓存更久 |

### 6.4 熔断 — pybreaker

```python
# 当 LLM API 连续失败 5 次 → 熔断 30 秒 → 快速失败而非堆积等待
import pybreaker

llm_breaker = pybreaker.CircuitBreaker(
    fail_max=5,          # 连续 5 次失败 → 熔断
    reset_timeout=30,    # 30 秒后半开尝试
)

@llm_breaker
def call_llm(messages):
    return llm_client.chat(messages)

# 调用时：
try:
    result = call_llm(messages)
except pybreaker.CircuitBreakerError:
    return {"error": "LLM 服务暂时不可用，请稍后重试"}
```

### 6.7 Agent 实例池

```python
# 预创建 Agent，复用实例（减少 LLM 连接开销）
from queue import Queue

class AgentPool:
    def __init__(self, size=10):
        self._pool = Queue(maxsize=size)
        for _ in range(size):
            self._pool.put(create_agent())  # Day3 工厂

    def acquire(self):
        return self._pool.get()             # 阻塞等待可用实例

    def release(self, agent):
        agent.clear()                       # 清理上下文
        self._pool.put(agent)               # 归还池中

# 使用：
agent = pool.acquire()
try:
    result = agent.run(question)
finally:
    pool.release(agent)
```

### 方向三详细：多模态文档处理 + RAG

```
用户上传 PDF/Word/图片
  → 文档解析（pymupdf / python-docx）
  → 文本分块（tiktoken 512 tokens/chunk）
  → 向量化（OpenAI text-embedding-3-small）
  → 存入 pgvector / ChromaDB
  → 用户提问 → 向量检索 Top5 → 注入 LLM context → 回答
```

**核心组件：**
| 步骤 | 工具 | 产出 |
|------|------|------|
| PDF 解析 | pymupdf / marker-pdf | 纯文本 + 表格 |
| Word 解析 | python-docx | 段落文本 |
| 图片理解 | CLIP / GPT-4V | 图片描述文本 |
| 文本分块 | tiktoken / langchain splitter | 512 token 块 |
| 向量化 | OpenAI Embedding / sentence-transformers | 1536 维向量 |
| 存储 | pgvector / ChromaDB / Qdrant | 向量索引 |
| 检索 | 余弦相似度 Top-K | 最相关段落 |
| 生成 | LLM + 检索上下文 | 最终回答 |

**简化实现（Day7 范围）：**
- `src/document_processor.py` — PDF/Word → 文本（pymupdf + python-docx）
- `src/rag_engine.py` — 分块 → 向量化 → 存储 → 检索（ChromaDB 内存模式）
- `src/vision.py` — 图片 → GPT-4V 描述（可选，教学演示）
