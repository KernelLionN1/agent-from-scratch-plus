## 二、核心洞察

| 洞察 | 说明 |
|------|------|
| 动态路由 ≠ 框架专属 | Day1 的 while 循环本质也是动态路由，LangGraph 只是用图表达 |
| `Annotated[list, add]` 是 reducer | 追加而非覆盖，LangGraph State 的核心机制 |
| SQLite 的 TEXT 没有性能问题 | 变长存储类，关键是加索引不是改类型 |
| `@property` 每次查库 | 看着像属性取值，实际每次 SELECT，需缓存 |
| 多租户需要分层 ID | 园区场景 4 层：campus → tenant → user → conversation |

## 三、工作流平台接入：Dify / n8n

### 3.1 应该放 Python AI 中台还是 Java 业务中台？

**结论：工作流定义在 Python AI 中台，业务触发在 Java 中台。**

```
Java 业务中台（流程稳定）            Python AI 中台（流程多变）
├─ 订单审批流                       ├─ Dify: RAG 问答流
├─ 用户权限、租户隔离               ├─ n8n: 定时爬数据 + 发报表
└─ 调用: POST /ai/workflow/xxx      └─ 你 Day5 的 DynamicAgent 图
```

**为什么 AI 工作流不该放 Java 端：**

```
放 Java: 改 prompt → 改代码 → 编译 → 发版 → 重启 → 5分钟
放 Python: 改 prompt → 改 Dify 画布 → 点发布 → 30秒
```

### 3.2 调用方式

```python
# Python AI 中台 — FastAPI 服务
@app.post("/workflow/price_inquiry")
async def price_inquiry(req: PriceRequest):
    result = dify_client.run_workflow(
        workflow_id="price_inquiry_v3",
        inputs={"product": req.product, "quantity": req.quantity}
    )
    return {"price": result["price"]}
```

```java
// Java 业务中台 — 只关心输入输出
public PriceResult inquirePrice(Product p, int qty) {
    return aiPlatformClient.post("/workflow/price_inquiry",
        Map.of("product", p.getCode(), "quantity", qty));
}
```

## 四、TypeScript Agent 项目（2025-2026）

GitHub 上值得关注的三个 TypeScript 本地 Agent 框架：

| 项目 | Stars | 特点 |
|------|:--:|------|
| **Mastra** (`mastra-ai/mastra`) | 8K+ | Gatsby 团队出品，Agent+Workflow+RAG+Memory 全家桶 |
| **Vercel AI SDK** (`vercel/ai`) | 20K+ | 最大 TS AI 框架，2.8M/周下载，前端集成极强 |
| **VoltAgent** (`voltagent/voltagent`) | 新项目 | 可观测性优先，MCP 协议支持 |

**Mastra 最像你正在做的事：**

```typescript
// TypeScript 版的 DynamicAgent
import { Agent } from "@mastra/core/agent";

export const weatherAgent = new Agent({
  id: "weather-agent",
  instructions: "你是天气助手...",
  model: "openai/gpt-4o",
  tools: { getWeather, searchLocation },  // ← 跟你的 tool_node 一个思路
});
```

  ┌─────────────────────────────┐
  │  TypeScript (前端 Agent UI)  │  ← 用户交互、流式渲染
  ├─────────────────────────────┤
  │  Python (Agent 编排引擎)     │  ← 多 Agent 协作、RAG、你 Day5 做的事
  ├─────────────────────────────┤
  │  Rust/Go (推理/工具执行)     │  ← llama.cpp、向量检索
  └─────────────────────────────┘

三者不是替代关系，是分层。Python 在编排层至少 3-5 年都是主战场。

### 5.1 对你（Java 开发者）的影响

- **Python Agent 编排** — 你现在的赛道，正确 ✅
- **TypeScript Agent** — 值得了解 Mastra，但不值得换语言
- **Java 业务中台** — 你的老本行，跟 Python AI 中台通过 HTTP 协作
- **Rust/Go 工具层** — 不用学，调 SDK 就行

### 5.2 数据清洗选型

Agent 场景下的数据清洗选 Python（同语言零序列化开销），不是 Python 比 Spark 强，而是"Agent 本身就是 Python 写的"这个事实决定的。TB 级以上才需要 Spark。

## 七、Python 知识速查

| Python | 说明 | Java 类比 |
|--------|------|-----------|
| `@property` | 方法伪装成属性 | `getXxx()` 但调用时不加括号 |
| `-> list` | 返回类型注解（不强制） | `List<T> getXxx()` |
| `Annotated[list, add]` | Reducer：更新时追加而非覆盖 | `List.addAll()` vs `list =` |
| `Literal["a", "b"]` | 返回值只能是这两个字符串 | `enum { A, B }` |
| `Optional[str]` | 可以是 str 或 None | `@Nullable String` |
