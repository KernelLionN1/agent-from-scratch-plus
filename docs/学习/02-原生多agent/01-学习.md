## 一、先理解：为什么需要多 Agent？

Day1 你写了一个单 Agent —— 一个 LLM 实例包揽所有事。这在简单场景下够用，但：

```
单 Agent（Day1）                      多 Agent（Day2）
┌──────────────────┐          ┌─────────────────────────────┐
│  用户 → Agent    │          │  用户                        │
│  (做所有事)       │          │   ↓                         │
│                  │          │  Planner ← 拆解需求          │
│  问题:            │          │   ↓                         │
│  - 一个大脑想所有  │          │  Coder → 写代码              │
│  - 没有分工       │          │   ↓                         │
│  - 没有审核       │          │  Reviewer → 检查质量          │
│                  │          │   ↓                         │
│                  │          │  用户 ← 最终结果              │
└──────────────────┘          └─────────────────────────────┘
```

**核心思想：分而治之。** 每个 Agent 有专属角色和 prompt，专注于自己擅长的事。这是软件工程里「单一职责原则」在 AI 领域的应用。

## 二、核心概念：角色定义（roles.py）

### 2.1 角色枚举（AgentRole）

```python
class AgentRole(Enum):
    PLANNER = "planner"     # 规划者：拆解需求 → 子任务列表
    CODER = "coder"         # 编码者：子任务 → 代码实现
    REVIEWER = "reviewer"   # 审核者：代码 → 审核意见
```

**Java 类比：**
```java
// 和你熟悉的 Java Enum 几乎一模一样
public enum AgentRole {
    PLANNER("planner"),
    CODER("coder"),
    REVIEWER("reviewer");
    
    private final String value;
    AgentRole(String value) { this.value = value; }
}
```

### 2.2 System Prompt — 角色的「人格」

每个角色有专属的 system prompt，告诉 LLM 「你是谁、你的职责是什么」：

| 角色 | Prompt 要点 | Temperature |
|------|------------|-------------|
| Planner | 任务规划专家，分析需求拆子任务 | 0.7（要有创造力） |
| Coder | Python 编程专家，根据描述生成代码 | 0.3（要精确） |
| Reviewer | 代码审核专家，检查正确性/可读性/性能 | 0.3（要精确） |

**为什么 Planner 用更高的 temperature？**
- 拆分任务需要发散思维，temperature=0.7 让它不那么死板
- 编码和审核需要精确，temperature=0.3 减少随机性

### 2.3 【刻意踩坑】角色 Prompt 边界模糊

```python
AgentRole.PLANNER: (
    "你是一个任务规划专家。"
    "你的职责是分析用户需求，将复杂任务拆分为可执行的子任务。"
    # ❗ 没有写「你只能规划，不能执行」
    # 这可能导致 Planner 越权直接写代码
),
```

**为什么要踩这个坑？**
1. 真实项目中 prompt 写得含糊，Agent 就会越界
2. 让你亲眼看到不设边界约束的后果
3. Day3 我们会加严格约束：「你只能规划，绝对不能写代码」

## 三、核心概念：消息总线（message_bus.py）

### 3.1 为什么需要消息总线？

三个 Agent 需要互相通信：
- Planner 告诉 Coder：「这是你的任务」
- Coder 告诉 Reviewer：「这是我写的代码」
- Reviewer 告诉 Coder：「这里有 3 个问题」

直接调用函数会让代码耦合死。消息总线是解耦层：

```
Planner ──→ MessageBus ──→ Coder
                │
                └────────→ Reviewer
```

**Java 类比：** 相当于 Spring 的 ApplicationEventPublisher + @EventListener，或者简化版的 Kafka/RabbitMQ。

### 3.2 消息格式（Message）

```python
@dataclass
class Message:
    sender: str       # 谁发的（"planner"）
    receiver: str     # 发给谁（"coder"）
    type: str         # 消息类型（"task" / "code" / "review"）
    content: str      # 消息内容
    id: str           # 唯一 ID（UUID 前 8 位）
    timestamp: float  # 创建时间
```

**Java 类比：** 相当于一个 immutable DTO，`@dataclass` 自动生成 `__init__`/`__repr__`/`__eq__`，对应 Java 的 Lombok `@Value` 或 `record`。

### 3.3 MessageBus 核心方法

```python
class MessageBus:
    def send(msg)           # 发送消息到指定接收方
    def broadcast(...)      # 向多个接收方发送同一消息
    def receive(receiver)   # 获取某接收方的所有消息
    def receive_since(...)  # 按时间增量拉取
    def receive_by_type(...)# 按消息类型过滤
```

### 3.4 【刻意踩坑】消息重复消费

```python
def receive(self, receiver: str) -> list[Message]:
    # ❗ 只读不删 —— 消息永远留在队列里
    return self._queues.get(receiver, [])
```

**后果演示（test_day2_phase1.py 验证 3）：**
```
第一次 receive: 1 条 → ID=2ff6f258
第二次 receive: 1 条 → ID=2ff6f258  ← 同一消息！
```

**类比 Java：**
```java
// 我们的 Bus 相当于只调了 peek() 而不调 poll()
Queue<Message> queue = new LinkedList<>();
Message msg = queue.peek();  // 拿到但不移除
Message msg2 = queue.peek(); // 还是同一个！
```

Day3 修复：增加 `consumed` 标记或改为 `pop` 语义。

## 四、代码走读

### 4.1 roles.py 结构

```
src/roles.py
├── AgentRole(Enum)        ← 角色枚举（3 个值）
├── ROLE_PROMPTS dict       ← 角色 → system prompt 映射
├── RoleConfig 类           ← 捆绑 role + prompt + temperature
├── get_role_prompt()       ← 便捷函数：拿 prompt
└── get_role_config()       ← 便捷函数：拿完整配置
```

### 4.2 message_bus.py 结构

```
src/message_bus.py
├── Message(@dataclass)     ← 消息 DTO
│   ├── to_dict()           ← 转 dict
│   └── __str__()           ← 友好打印
├── MessageBus              ← 消息总线核心
│   ├── send()              ← 发送
│   ├── broadcast()         ← 广播
│   ├── receive()           ← 接收（踩坑：不删除）
│   ├── receive_since()     ← 增量拉取
│   ├── receive_by_type()   ← 按类型过滤
│   ├── stats()             ← 统计信息
│   └── clear()             ← 清空
```

## 五、Java 开发者对照表

| Python 概念 | Java 等价 | 说明 |
|------------|----------|------|
| `AgentRole(Enum)` | `enum AgentRole {}` | 完全相同的枚举 |
| `ROLE_PROMPTS: dict` | `Map<AgentRole, String>` | 角色→prompt 映射 |
| `@dataclass` | `record` 或 Lombok `@Value` | 自动生成构造器/equals/toString |
| `MessageBus._queues` | `Map<String, List<Message>>` | 按接收方分组的消息队列 |
| `field(default_factory=...)` | 构造器中 `this.id = UUID.randomUUID()` | 默认值生成 |
| `time.time()` | `System.currentTimeMillis() / 1000.0` | Unix 时间戳 |
| `list[Message]` | `List<Message>` | 类型提示 ≈ 泛型 |
| `str | None` | `Optional<String>` | 可空类型 |

## 六、动手实验

### 实验 1：观察角色 prompt 对 LLM 行为的影响

```python
from src.llm_client import LLMClient
from src.roles import get_role_config, AgentRole

client = LLMClient()
planner_cfg = get_role_config(AgentRole.PLANNER)

# 用 Planner 的 prompt 问同一个问题
response = client.chat(
    messages=[
        {"role": "system", "content": planner_cfg.prompt},
        {"role": "user", "content": "帮我写一个排序算法"}
    ],
    temperature=planner_cfg.temperature,
)
print("Planner 回答:", response["content"])
# 观察：Planner 会自己写代码吗？还是会只给规划？
```

### 实验 2：模拟多 Agent 通信

```python
from src.message_bus import MessageBus, Message

bus = MessageBus()

# Planner 发布任务
bus.send(Message(
    sender="planner", receiver="coder",
    type="task", content="实现二分查找"
))

# Coder 提交代码
bus.send(Message(
    sender="coder", receiver="reviewer",
    type="code", content="def binary_search(arr, target): ..."
))

# Reviewer 给出意见
bus.send(Message(
    sender="reviewer", receiver="coder",
    type="review", content="缺少边界检查，建议加 len(arr)==0 判断"
))

# 查看完整通信历史
for agent in ["coder", "reviewer"]:
    msgs = bus.receive(agent)
    print(f"\n{agent} 的收件箱 ({len(msgs)} 条):")
    for m in msgs:
        print(f"  [{m.type}] from {m.sender}: {m.content[:50]}...")
```

### 实验 3：验证消息重复消费的影响

```python
bus = MessageBus()
bus.send(Message(sender="p", receiver="c", type="task", content="任务1"))

# 模拟 Agent 循环 —— 每次循环都 receive()
for i in range(5):
    msgs = bus.receive("c")
    print(f"第{i+1}次: {len(msgs)} 条消息")
    # 如果没有去重逻辑，每轮都会处理同一消息！
```

## 七、阶段一小结

| 学到了什么 | 对应知识点 |
|-----------|----------|
| 多 Agent 为什么需要角色分工 | 单一职责原则在 AI 系统中的应用 |
| 不同角色为什么用不同 temperature | 精确任务（代码/审核）低温，创意任务（规划）高温 |
| 消息总线如何解耦 Agent 通信 | 发布-订阅模式的简化实现 |
| 消息不消费会有什么后果 | 重复处理、无限循环 —— Day3 修复 |
| 角色 prompt 模糊会有什么后果 | Agent 越权 —— Day3 收紧约束 |
