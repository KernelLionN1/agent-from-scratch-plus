## 一、先理解：为什么要把 Agent 变成 HTTP 服务？

目前你只能这样用 Agent：

```python
# Python REPL 里手动调
from src.agent import ReActAgent
agent = ReActAgent()
agent.run("帮我算 1+1")
```

问题：除了你以外，没人能用。前端、移动端、其他服务都无法访问。

FastAPI 做的事情：**把 Python 函数变成 HTTP 接口**。

```
curl POST /chat             →   agent.run(message)   →   返回 JSON
前端 fetch("/chat")         →      (同一个)          →   渲染到页面
```

## 二、核心概念

### 2.1 FastAPI 是什么？

Python 的 Web 框架，对标 Java 的 Spring Boot + Spring MVC。

```python
# FastAPI
@app.post("/chat")
def chat(request: ChatRequest) -> ChatResponse:
    answer = agent.run(request.message)
    return ChatResponse(answer=answer)

# Spring Boot 对应写法
@PostMapping("/chat")
public ChatResponse chat(@RequestBody ChatRequest request) {
    String answer = agent.run(request.getMessage());
    return new ChatResponse(answer, "ok");
}
```

### 2.2 Pydantic —— 自动参数校验

```python
class ChatRequest(BaseModel):
    message: str = Field(..., min_length=1, max_length=2000)
```

当你发空消息时，Pydantic 自动返回 422：

```json
{"detail": "String should have at least 1 character"}
```

不需要手写 `if (message == null || message.isEmpty())` 了。

### 2.3 TestClient —— 进程内测试

```python
from fastapi.testclient import TestClient
client = TestClient(app)

response = client.post("/chat", json={"message": "你好"})
# 等价于 HTTP POST，但不走网络，直接调函数
```

对应 Java 的 `MockMvc`：

```java
mockMvc.perform(post("/chat").content("{\"message\":\"你好\"}"))
```

## 三、代码详解

### 3.1 api.py 结构

```
FastAPI app
├── GET  /              → 健康检查（服务是否活着）
├── GET  /health        → 详细健康信息（Agent 状态）
├── POST /chat          → 核心：发消息给 Agent
└── POST /chat/reset    → 重置对话记忆
```

### 3.2 三个阶段踩坑点集中在 api.py

| 坑点 | 代码位置 | 问题 | 生产环境正确做法 |
|------|---------|------|----------------|
| 全局 Agent 实例 | `agent = ReActAgent()` 模块级变量 | 所有用户共享 memory，互相污染 | 每个请求新建 Agent 或按 session_id 隔离 |
| 同步 def | `def chat()` 而非 `async def` | 阻塞事件循环，并发差 | 用 `async def` + 线程池执行 |
| 无超时控制 | `agent.run()` 无 timeout | LLM 卡住时请求永远挂起 | 加 `asyncio.wait_for()` 或线程超时 |
| 粗粒度异常 | 只返回 500 | 无法区分超时/认证/参数错误 | 区分异常类型返回不同状态码 |

**为什么要刻意写这些坑？** —— 阶段四是 Day1 收尾，把所有前面的坑集中暴露在 API 层。Day3 联调时会逐一修复。

## 五、动手实验

### 1. 验证全局 Agent 污染

启动服务后，开两个终端：

```bash
# 终端 1
curl -X POST http://localhost:8000/chat \
     -d '{"message": "我叫张三，记住我的名字"}'

# 终端 2
curl -X POST http://localhost:8000/chat \
     -d '{"message": "我叫什么名字？"}'
# → 返回"张三" ← 两个用户共享了 memory！
```

### 2. 模拟阻塞

把 agent 的 `max_iterations` 设为 100，然后同时发两个请求，观察第二个是否被阻塞。

### 3. 修改为每个请求独立 Agent

把全局 `agent` 删除，在 `chat()` 里每次新建：

```python
@app.post("/chat")
def chat(request: ChatRequest):
    agent = ReActAgent()  # ← 每个请求一个独立实例
    answer = agent.run(request.message)
    return ChatResponse(answer=answer)
```

再跑实验 1，看污染是否消失。

## 六、Java 开发者对照

| Java 概念 | FastAPI 对应 |
|-----------|------------|
| `@RestController` | `@app.post("/chat")` |
| `@RequestBody` | `request: ChatRequest` |
| `ResponseEntity<T>` | `ChatResponse` (Pydantic) |
| `@Valid` 参数校验 | Pydantic `Field(min_length=1)` |
| `MockMvc` | `TestClient(app)` |
| `@SpringBootApplication` | `main.py` + `uvicorn.run()` |
| `application.yml` server.port | `uvicorn.run(port=8000)` |
| Swagger / springdoc | FastAPI 自动生成 `/docs` |
