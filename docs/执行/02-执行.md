## 阶段一：角色定义 + 消息总线

> 时间：2026-06-16  |  产出：`src/roles.py`、`src/message_bus.py`、`test_day2_phase1.py`、`docs/学习/02-原生多agent/01-学习.md`

### 做了什么

1. **`src/roles.py`** — 角色定义模块
   - `AgentRole` 枚举：PLANNER / CODER / REVIEWER
   - `ROLE_PROMPTS`：每个角色的 system prompt（刻意写得模糊）
   - `RoleConfig`：捆绑 role + prompt + temperature
   - Planner temperature=0.7（需要创造力），Coder/Reviewer=0.3（需要精确）

2. **`src/message_bus.py`** — 消息总线
   - `Message` dataclass：标准化消息格式（sender/receiver/type/content/id/timestamp）
   - `MessageBus` 类：send / broadcast / receive / receive_since / receive_by_type
   - 内部用 dict[str, list[Message]] 按接收方存储

3. **`test_day2_phase1.py`** — 5 项验证全部通过
   - 验证 1：角色定义完整性
   - 验证 2：消息基本收发 + 隔离性
   - 验证 3：【踩坑】消息重复消费确认
   - 验证 4：广播 + 过滤 + 增量拉取
   - 验证 5：统计信息

4. **`docs/学习/02-原生多agent/01-学习.md`** — 学习指南
   - 概念讲解 + 代码走读 + Java 对照表 + 3 个动手实验

### 踩坑确认

| 坑点 | 验证结果 | 代码位置 |
|------|---------|---------|
| 消息重复消费 | ✅ 确认：同 ID 消息被 receive() 多次返回 | `message_bus.py:receive()` |
| 角色 Prompt 模糊 | ✅ 预留：prompt 不含禁止越权的约束 | `roles.py:ROLE_PROMPTS` |

### 决策记录

- 消息总线用 dataclass 而非普通类 —— Python 3.7+ 标准，对应 Java record
- receive() 只读不删是有意设计，用于教学演示重复消费问题
- 角色 prompt 故意不写「只能...不能...」约束，等 Day3 收紧
