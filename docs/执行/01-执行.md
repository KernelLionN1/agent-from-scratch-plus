封装 DeepSeek API 调用，通过 `python-dotenv` 读取 `.env` 配置。

- `LLMClient.chat(messages, tools, ...)` → 返回 `{"content", "tool_calls", "model", "usage"}`
- `_parse_tool_calls(message)` → 从 OpenAI Response 中提取 function_call

### src/tools.py

| 工具 | 功能 | 刻意踩坑点 |

# 阶段二：ReAct Agent 循环

> 时间：2026-06-16  |  产出：`src/agent.py`、`test_phase2.py`、`docs/学习/02-学习.md`

## 创建文件

### src/agent.py

ReActAgent 类，核心是 `run()` 方法里的 `while True` 循环：

```
Think → LLM 决定下一步（说话 or 调工具）
  Act → 执行 LLM 请求的工具
    Observe → 工具结果反馈给 LLM
      Think → 基于结果再决定...
```

- `__init__()`: 组装 LLM 客户端 + 工具定义 + 系统提示词
- `run(user_message)`: 构建 messages → while True → 调 LLM → 执行工具 → 结果反馈 → 直到 LLM 给出最终答案
- `run_agent(question)`: 便捷函数，一行启动 Agent

### test_phase2.py

4 个测试用例：纯计算 / 知识查询 / 纯对话 / 复合问题

## 测试结果

| 测试 | 预期 | 实际 | 分析 |
|------|------|------|------|
| 计算 45678+12345 | 调 calculator → 返回结果 | LLM 说"好的我来算"但没调工具 | system prompt 太弱，不强制使用工具 |
| 查 DeepSeek | 调 search_knowledge → 返回介绍 | 调了工具但返回 {} → LLM 放弃 | 搜索逻辑简陋 + 无重试机制 |
| 自我介绍 | 直接回答 | ✅ 正常 | 不需要工具 |
| 复合问题 | 先查后算 | LLM 口头答应但没执行 | 同测试 1，缺少工具强制 |

### 踩坑点已暴露

- **LLM 不调工具**：提示词需要更强约束
- **空结果无重试**：工具失败时缺少降级策略
- **无轮次上限**：`while True` 可能死循环

# 阶段三：对话记忆 + 上下文截断

> 时间：2026-06-16  |  产出：`src/memory.py`、`src/agent.py`(重构)、`test_phase3.py`、`docs/学习/03-学习.md`

## 创建文件

### src/memory.py

`ConversationMemory` 类 —— 持久存储对话消息 + 三种截断策略：

| 策略 | 行为 | 适用场景 |
|------|------|---------|
| `none` | 不截断，返回全部 | 短对话（坑点：超长会报错） |
| `sliding_window` | 保留 system + 最近 N 条 | 对话式应用 |
| `token_limit` | 按字符数/4 估算 token，超限裁剪 | 成本控制（坑点：估算极不准） |

关键方法：
- `add_user/assistant/tool_result()` → 追加消息
- `get_messages(strategy)` → 返回截断后的消息列表
- `clear()` → 清空记忆
- `set_system()` → 设置/替换系统提示词

### src/agent.py（重构）

核心变化：
- `__init__()` 新增 `max_iterations` 防止死循环 + `truncation_strategy` 选择截断方式
- `run()` 不再每次新建 messages，改为往 `self.memory` 追加并从 memory 取
- 新增 `clear_memory()` / `set_truncation()` / `memory_stats()` 方法
- LLM 回答和工具结果都自动存入 memory

### test_phase3.py

4 个测试：多轮记忆 / 滑动窗口截断 / Token 限制截断 / 记忆+工具混合

## 测试结果

| 测试 | 结果 | 现象 |
|------|------|------|
| 多轮记忆 | ✅ | "你刚才说你30岁" → 正确记住 |
| 滑动窗口 | ✅ | max_messages=4，仍能记住早期关键信息 |
| Token限制 | ✅ | max_tokens=300 下正常运行 |
| 工具+记忆 | ⚠️ | 工具调用仍需强化 system prompt |

## 阶段二 → 阶段三 对比

```
阶段二：每次 run() 新建 messages → 无记忆 → 无法多轮对话
阶段三：messages 存入 memory → 跨 run() 保留 → 支持多轮对话
        + max_iterations 防止死循环
        + 三种截断策略防止上下文超限
```
