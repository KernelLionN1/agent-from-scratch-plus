## 分天详细执行计划（每日8小时 + GLM使用指引 + 刻意踩坑点）
### Day1 原生单Agent（8h）
**目标**：从零手搓完整ReAct Agent，对接FastAPI，吃透底层调用逻辑
1. 前2h：基础LLM调用 + 自定义工具（计算器、文本查询）
   - 踩坑：不做入参校验、工具返回值不清洗；让GLM辅助梳理调用模板，逐行解读再编码
2. 中间2.5h：手写`while`循环实现ReAct思考-行动-观察闭环
   - 踩坑：不设最大轮次导致死循环、硬编码解析规则引发格式报错；卡顿时让GLM定位循环/解析问题
3. 后2h：增加对话记忆 + 上下文截断
   - 踩坑：无消息截断，触发上下文超限；向GLM请教主流截断方案优劣
4. 最后1.5h：封装FastAPI异步接口，增加基础超时
   - 踩坑：同步接口引发阻塞；GLM协助写异步、超时控制代码

**当日产出**：纯原生单Agent + 可调用API

---

### Day2 原生多Agent（对标multi-agent-coder）（8h）
**目标**：完成多角色分工、消息总线、调度逻辑，复刻multi-agent-coder核心架构
1. 前2h：角色定义（规划/编码/审核Agent）+ 简易消息总线
   - 踩坑：消息重复消费、角色Prompt边界模糊；让GLM输出角色分工架构图、提示词模板
2. 中间2.5h：串行任务分发 + 基础流转逻辑
   - 踩坑：任务拆分不合理、执行顺序混乱；分析串行架构优缺点
3. 后2h：改造为并行执行 + 结果统一汇总
   - 踩坑：并行无等待逻辑、输出格式不统一；GLM协助编写异步调度、数据标准化代码
4. 最后1.5h：全局状态变量设计
   - 踩坑：全局变量滥用导致状态错乱；梳理原生多Agent状态管理痛点

**当日产出**：基础版多Agent协作系统

---

### Day3 多Agent联调 + 集中踩坑&修复（8h）
**目标**：把前两日所有故意埋下的问题全部复现、排查、修复，强化排错能力（面试高频考点）
1. 前3h：全流程联调，复现问题：消息乱序、任务重复执行、单Agent故障导致整体瘫痪
2. 中间2.5h：补充**失败重试、熔断、任务终止机制**
3. 后2h：统一对接FastAPI，全链路压力自测
4. 最后0.5h：记录当日所有坑点与解决方案

**当日产出**：稳定可用的**原生完整版多Agent系统**

### Day4 LangChain + LangGraph 框架重构（8h）
**目标**：用框架重构两套代码，对比原生实现，理解框架价值
1. 前2.5h：LangChain重构单Agent，迁移工具、记忆模块
   - 踩坑：组件版本冲突、Chain拼接顺序错误；GLM协助排查版本、组件搭配问题
2. 中间3h：LangGraph重构多Agent，实现状态节点、条件跳转
   - 踩坑：状态定义错误、条件边逻辑异常、断点失效；重点练习状态图编写
3. 后2.5h：双版本（原生+框架）对照测试，总结差异
   - 向GLM提问：`原生手写Agent和LangGraph框架实现的优劣、面试常问对比问题`

**当日产出**：框架版单/多Agent项目

## 关键提速技巧（适配Java老开发 + GLM用法）
1. **复用Java工程思维**
   你熟悉分层、解耦、异常处理、配置管理，在写Python代码时直接沿用这套思想，不用重新理解工程理念，大幅提速；FastAPI、目录结构可以类比SpringBoot快速上手。
2. **GLM使用原则（提速+保学习效果）**
   - 优先要**思路、架构、报错分析**，代码模板参考后手动改写，不直接复制；
   - 复杂状态图、多Agent流转，先让GLM出流程图，再动手编码；
   - 每阶段结束立刻让GLM提炼面试考点，边学边备面试。
3. **刻意踩坑不省略**
   压缩周期但**保留所有预设坑点**，这是面试区分度的关键，也是短期加深记忆的核心。
4. 工具前置准备
   提前克隆`multi-agent-coder`、`openharness`仓库，装好Python、依赖包、IDE插件，避免每日耗时在环境配置上。
