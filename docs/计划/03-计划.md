### 1.2 Day1 踩坑修复（1.5h）

| # | 坑点 | 文件 | 修复方案 |
|---|------|------|------|
| 1 | eval() 安全漏洞 | `tools.py` | 用 `ast.literal_eval()` 替代 `eval()`，限制表达式类型 |

## 阶段二：失败重试 + 熔断机制（2.5h）

### 2.1 LLM 调用重试（1h）

- [ ] `LLMClient.chat()` 加指数退避重试（最多 3 次）
- [ ] 可重试错误：网络超时、429 限流、5xx 服务端错误
- [ ] 不可重试错误：401 认证失败、400 参数错误（直接抛）
- [ ] 重试间隔：1s → 2s → 4s（指数退避）

文件：`src/llm_client.py`

### 2.2 并行任务容错（0.5h）

- [ ] `asyncio.gather()` 加 `return_exceptions=True`
- [ ] 收集部分成功结果 + 记录失败任务
- [ ] 一个 Coder 挂了不影响其他 Coder

文件：`src/orchestrator.py → run_parallel()`

### 2.3 超时保护 + 部分结果收集（0.5h）

- [ ] `run_parallel()` 默认加超时（120s）
- [ ] 超时后不丢弃已完成结果
- [ ] `run_parallel_with_timeout()` 改造为收集已完成结果

文件：`src/orchestrator.py → run_parallel_with_timeout()`

### 2.4 乐观锁自动重试（0.5h）

- [ ] `SharedState.update()` 失败时自动重试（最多 3 次）
- [ ] 每次重试：重新读最新值 → 重新计算 → 再尝试更新
- [ ] 三次都失败则返回失败，记录到 errors

文件：`src/shared_state.py`

## 阶段三：Agent 行为修复（1.5h）

### 3.1 角色 Prompt 收紧（0.5h）

- [ ] Planner：限制子任务数量（3-8 个），要求用 `### 子任务 N` 格式
- [ ] Coder：明确"你只负责编写代码，不做需求分析"
- [ ] Reviewer：要求输出结构化审核意见（4 维度：正确性/可读性/性能/安全性）

文件：`src/roles.py`

### 3.2 输出格式统一（0.5h）

- [ ] Planner 输出格式：`### 子任务 N：标题\n描述`
- [ ] Coder 输出格式：要求返回纯代码 + 可选解释
- [ ] Reviewer 输出格式：结构化 Markdown（含改进代码）

文件：各 Agent 的 `execute()` 方法

### 3.3 消息总线修复（0.5h）

- [ ] 增量消费：加 `since_id`，只返回新消息
- [ ] 消息去重：同一 sender+type+content 组合去重
- [ ] 执行顺序：加依赖检查，Reviewer 确认 Coder 完成后再执行

文件：`src/message_bus.py`
