# Day1：原生单Agent 每日计划

> 总时长：8h  |  目标：从零手搓完整 ReAct Agent，对接 FastAPI，吃透底层调用逻辑  
> 当日产出：纯原生单Agent + 可调用API

---

## 环境验证（开始前 15min）

- [ ] Python ≥ 3.10 可用
- [ ] 创建虚拟环境 `python -m venv venv` 并激活
- [ ] 安装基础依赖：`openai`（或对应LLM SDK）、`fastapi`、`uvicorn`、`pydantic`
- [ ] API Key 可用，跑通一次最简单的 LLM 调用
- [ ] IDE 就绪（VSCode / PyCharm）

---

## 阶段一：基础 LLM 调用 + 自定义工具（2h）

### 任务清单

- [ ] 封装 LLM 调用函数（支持 system prompt + user message）
- [ ] 实现工具注册机制（字典映射 工具名 → 函数）
- [ ] 编写第一个工具：计算器（加减乘除，字符串输入 → 数值结果）
- [ ] 编写第二个工具：文本查询（模拟知识库 / 本地文件查询）
- [ ] 实现工具调用解析：从 LLM 响应中提取 function_call，执行并返回结果

### 刻意踩坑（不要跳过）

| 坑点 | 说明 |
|------|------|
| 入参不校验 | 工具函数不验证参数类型/范围，看 LLM 传错参数时怎么炸 |
| 返回值不清洗 | 工具返回原始 dict/对象，不转成字符串，观察 LLM 能不能消化 |
| 工具描述模糊 | 先写含糊的工具描述，体验 LLM 误调用，再对比精确描述的差异 |

### 产出

- [ ] `src/tools.py` — 工具注册 + 计算器 + 文本查询
- [ ] `src/llm_client.py` — LLM 调用封装
- [ ] 测试脚本：单轮工具调用跑通

---

## 阶段二：手写 ReAct 循环（2.5h）

### 任务清单

- [ ] 手写 `while True` 循环，实现 思考 → 行动 → 观察 闭环
- [ ] 解析 LLM 响应：区分「最终回答」和「工具调用」
- [ ] 工具调用结果注入回消息列表，继续循环
- [ ] 设定最大轮次上限（如 10 轮），防止死循环
- [ ] 处理 LLM 返回格式异常（非 JSON、缺少字段等）

### 刻意踩坑（不要跳过）

| 坑点 | 说明 |
|------|------|
| 不设最大轮次 | 先不限制循环次数，跑一个复杂问题看是否死循环 |
| 硬编码解析 | 用简单字符串匹配解析 function_call，不用标准 JSON 解析，看各种边界情况 |
| 无格式容错 | LLM 返回格式稍有偏差就崩溃，记录所有遇到的格式异常 |

### 产出

- [ ] `src/agent.py` — ReAct Agent 核心循环
- [ ] 能独立跑通：输入问题 → Agent 自动调用工具 → 返回最终答案

---

## 阶段三：对话记忆 + 上下文截断（2h）

### 任务清单

- [ ] 实现消息历史存储（list[dict]）
- [ ] 每次对话追加 user/assistant/tool 消息
- [ ] 实现上下文截断策略：保留最近 N 条消息 + 保留 system prompt
- [ ] 实现 token 估算（简单版：按字符数/4 估算）
- [ ] 对比不同截断策略的效果

### 刻意踩坑（不要跳过）

| 坑点 | 说明 |
|------|------|
| 无截断 | 连续对话 20 轮不截断，观察何时触发上下文超限报错 |
| 简单截断 | 只保留最近 N 条，看丢失早期上下文后 Agent 表现 |
| 总结压缩 | 对比「滑动窗口截断」vs「对历史做摘要压缩」的差异 |

### 产出

- [ ] `src/memory.py` — 消息管理 + 截断逻辑
- [ ] 多轮对话测试：5 轮以上仍能保持上下文连贯

---

## 阶段四：FastAPI 封装 + 超时控制（1.5h）

### 任务清单

- [ ] 定义 API 请求/响应模型（Pydantic）
- [ ] 实现 `POST /chat` 异步接口
- [ ] 添加请求超时控制（如 60s）
- [ ] 处理并发请求（多个用户同时调用）
- [ ] 基础错误处理：超时返回 504，LLM 异常返回 500

### 刻意踩坑（不要跳过）

| 坑点 | 说明 |
|------|------|
| 同步阻塞 | 先用同步 `def` 写接口，压测观察阻塞现象 |
| 无超时 | 不设超时，模拟 LLM 响应慢的场景 |
| 全局状态 | Agent 用全局变量存状态，观察并发时状态互相覆盖 |

### 产出

- [ ] `src/api.py` — FastAPI 应用 + `/chat` 端点
- [ ] `main.py` — 启动入口
- [ ] 测试：`curl` 或 `httpx` 调通 API
